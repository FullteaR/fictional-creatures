# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project does

Generates fictional creature ("endemic life") cards in the style of a field guide. Each card combines:
1. A Japanese monster name generated by a Markov chain trained on `src/monsterNames.txt`
2. A description and scientific name generated via LLM (Qwen3.8-27B running locally via llama.cpp)
3. An image generated by the Anima model (`novaAnimeAM_v40.safetensors`), served by a ComfyUI container over HTTP
4. A composite image with styled caption overlay rendered using `ipagp.ttf`

Output images are saved to `src/endemic/`. There are two front ends: the notebook
(`src/monster-generator.ipynb`) and a web UI (`web/`, its own container) — see *Web UI* below.

## Running the project

All services run via Docker Compose. GPU is required.

```bash
# Start everything (downloads LLM, starts llama-server + ComfyUI, starts Jupyter)
docker compose up

# Unit tests — no GPU, no LLM, ~4s
docker compose exec app python -m pytest /mnt/tests -q

# Web UI — generate and browse the collection from a browser
# http://localhost:28081

# Access Jupyter notebook
# http://localhost:28080
# Open src/monster-generator.ipynb and run cells

# ComfyUI web UI (useful for debugging workflows by hand)
# http://localhost:8188
```

The `model-downloader` service runs first, downloading `unsloth/Qwen3.8-27B-GGUF` (UD-Q4_K_S quant) into `./models/`, plus the vision projector from `ggml-org/Qwen3.8-27B-GGUF`. The `llama-server` service then serves it via llama.cpp at `http://llama-server:8080/v1`. The `comfyui` service serves image generation at `http://comfyui:8188`, with `./models/comfyui` mounted as its model root. The `app` service runs JupyterLab at port 28080, with `./src` mounted at `/mnt`, and
`webui` serves the browser front end at port 28081 with `./src` at `/mnt` and `./web` at `/web`.

Image model weights are **not** downloaded automatically — see *Image models* below.

`llama-server` needs ~36s to load its 12GB GGUF and `comfyui` ~14s to import; both carry a healthcheck and `app` waits on `condition: service_healthy`, so Jupyter only becomes reachable once both back ends answer. Without that gate a plain `depends_on` returns as soon as the containers *start*, and running the notebook right away fails with a connection error. `llama-server`'s check hits `/health`, which llama.cpp answers 503 on until the model is resident.

Both back ends — `llama-server` and `comfyui` — set `restart: unless-stopped`, so they come back on their own if they die, and because `unless-stopped` also survives a daemon restart they return by themselves after a host reboot. `app` and `webui` do not, so a reboot still needs `docker compose up` to get them back.

`webui` deliberately does **not** wait on `service_healthy` the way `app` does, so its page opens whether or not the back ends are up. Pressing the button with one of them down fails and puts the connection error on screen, which is more use than a container that refuses the connection outright.

## Architecture

### Generation pipeline (`src/pipeline.py`)

`generate_card()` is the whole of it, and both front ends call it — the notebook's loop is three
lines and `web/server.py` runs the same function on a worker thread. The tables, the fonts and the
name generator live here too, so there is one place to change any of it.

1. **Name**: `MarkovMonsterNameGenerator` (bigram Markov chain) generates a Japanese katakana name, rejecting names too similar (Levenshtein distance ≤ 1-2) to training names. Training is 6360 names against every candidate, so `pipeline.name_generator()` trains once and hands back the same instance. The corpus started as ~4250 game-monster names and had ~2100 added — real Japanese species names, mineral and star names, and katakana place names — which is what stops every name sounding like the same franchise. `valid_name()` rejects anything that is a substring of a training name, so a real species name can never come out verbatim; what carries over is the sound, not the word. It skips the Levenshtein call when the two names differ in length by more than 2 (the distance cannot then be ≤2 anyway), since that scan is otherwise the most expensive thing in name generation.
2. **Target string**: `build_target()` combines random habitat (`FIELDS`, 108 entries) + random species type (`SPECIES`, 48) + name into a description target like `「深海にて観測される架空の魚「ミロカルガン」」`. Any of the three can be pinned instead; a name given by hand does not get the 貝/草/鳥/魚/虫/苔 suffix, since you asked for that exact name. `random.choice` over `FIELDS` is uniform, so the only way to shift where creatures live is to change the counts — forest and water alone used to be 32 of 56 entries, and the habitats added since were deliberately everything but.
3. **Hidden traits** (`textGenerateUtils.pick_traits`): danger to humans, population, the body plan, the size, the colour scheme, the body surface, the description's register, and the composition of the plate, drawn from weighted tables in code. None of it reaches the card as text — see *Hidden settings* below.
4. **Text generation** (`textGenerateUtils.py`): one LLM call each, few-shot prompted with `sampleMonsters.py` examples:
   - `generate_description`: 3-5 sentence Japanese description, in the rolled register and following the rolled body plan
   - `generate_profile`: the hidden spec sheet (size, colour, head, limb counts, organs, diet, danger, population, behaviour, habitat detail) — generated *after* the description and conditioned on it, so it elaborates without contradicting what the card says
   - `generate_prompt`: English image prompt (comma-separated descriptors; Anima's Qwen text encoder has no 77-token limit, so long prompts pass through intact), written from the description **and** the profile
   - `generate_scientific_name`: two-word Latin scientific name, reduced to its first line
5. **Image generation** (`imageGenerateUtils.py`): prepends `STYLE_PREFIX` (see *Keeping the output from looking AI-generated*), POSTs a ComfyUI API-format workflow to `comfyui:8188`, polls `/history/{prompt_id}`, fetches the PNG via `/view`. Generates at 1280×768 and downscales to 800×480. The seed is drawn once in `pipeline.generate_card` and used for **every** generation of that card — see *Checking the plate against the card* below. **This and the proofread that follows it are the only feedback passes in the pipeline, and each looks at the finished picture** — an earlier blanket self-refinement loop over every text call was removed; it doubled the LLM calls and, on the scientific name, "improved" a two-word binomial into a paragraph of Japanese, whose width then pushed the whole caption off the canvas.
6. **Proofreading** (`textGenerateUtils.review_description`): the chosen plate and the description go back to the vision model one last time, one sentence per line, and a sentence the picture contradicts is replaced — see *Correcting the card against the plate* below. The plate is fixed by then, so this is the only pass that edits the other side.
7. **Polishing** (`textGenerateUtils.polish_description`): the description alone, with no image, goes back to the model one sentence per line, and a sentence whose Japanese does not parse is replaced — see *Fixing the Japanese itself* below. It runs last because the pass above it edits the card too.
8. **Saving**: `<YYYYmmdd-HHMMSS>-<name>.png` in `src/endemic/`, and nothing else — the description as it goes on the card, as it was first written and as the plate left it, the hidden profile, the first prompt, every review round with the prompt and negative it ran under, the seed and the rolled traits ride inside the PNG as iTXt text chunks rather than in a file beside it. PNG does have an `eXIf` chunk, but almost nothing writes one; tEXt/iTXt is what ComfyUI and A1111 use, and iTXt is UTF-8 so Japanese survives where tEXt (Latin-1) would not. `Title` / `Description` / `Creation Time` / `Software` are the spec's standard keywords, so a generic viewer shows them; the rest goes in one `Endemic` key as JSON. Nothing here reads it back — it is there for whatever opens the PNG next. It costs ~3KB for a card that passed first time and ~7KB for one that ran three rounds, since each round keeps the prompt it ran under. `seed`, `rounds` and `chosen_round` are there to be measured against later: the seed plus a round's prompt and negative reproduces that exact plate, and the verdicts say which checklist items each round failed. The notebook used to save `<loop index>-<name>.png`, which collided between runs — `src/endemic/` still has three different `0-*.png` — and the hidden profile only ever reached stdout.
9. **Captioning** (`imageGenerateUtils.py:add_caption`): wraps the description on Japanese word boundaries found with `janome` — see *Breaking the caption into lines* below — and overlays a semi-transparent rounded rectangle at a random corner of the image. The scientific name is set in italic. `ipagp.ttf` has no italic face, so the binomial — and only the binomial, not the `(学名: )` label — is drawn in `src/NotoSerif-Italic.ttf` (Noto Serif Italic, OFL-1.1, license alongside it; override with `ITALIC_FONT`). That font covers Latin/Greek/Cyrillic only, so when the model returns a non-Latin scientific name `drawItalicText` falls back to shearing `ipagp` glyphs rather than rendering tofu. Because the two faces have different ascents, the label and the name are aligned on the baseline (`anchor="ls"`), not the top. The corner offsets are clamped to the canvas, so unexpectedly long text degrades to a top-left caption rather than being drawn off-screen.

Progress comes back through the optional `emit` argument. Omit it — which is what `web/server.py`
does — and `call_llm` prints the streamed tokens itself, exactly as it always has; pass
`pipeline.console_emit`, which is what the notebook does, and each step is labelled as it runs.
`emit` is a plain callback taking one dict, so anything that wants to follow a generation can
supply its own. `generate_card` returns `(card, image)`: the metadata dict that also goes into the
PNG's text chunks, and the finished image, which the notebook needs for its contact sheet.

`imageGenerateUtils.require_models()` is the preflight the notebook runs before the loop. It asks
ComfyUI whether all three weight files are visible and raises if one is not, rather than letting
the first card die inside a node validation error.

### Image client (`imageGenerateUtils.py`)

`get_image()` builds the ComfyUI workflow graph in code (`_build_workflow`) rather than loading a saved JSON, mirroring the official *Text to Image (Anima Base v1.0)* template: `UNETLoader` → `CLIPLoader`(type `stable_diffusion`) → `CLIPTextEncode` ×2 → `EmptyLatentImage` → `KSampler`(euler_ancestral/normal, 30 steps, cfg 5) → `VAEDecode` → `SaveImage`.

`get_image(seed=...)` pins the sampler's seed; left out it draws its own. `pipeline` passes the same seed to the draft and to the retry, which is what makes the review pass an A/B rather than two unrelated draws — see *Checking the plate against the card*.

Anima ships as three separate files, so all three loaders are needed — a single-file SDXL checkpoint would use `CheckpointLoaderSimple` instead. Override any of them via `COMFYUI_DIFFUSION_MODEL` / `COMFYUI_TEXT_ENCODER` / `COMFYUI_VAE`, and the server via `COMFYUI_URL`.

### Keeping the output from looking AI-generated

The booru quality-tag stack — `masterpiece, best quality, absurdres, 8k, ultra-detailed` plus `cinematic lighting, dramatic shadows, volumetric lighting` — is what produces oversaturated, over-rendered, glowing "AI art". It used to lead the few-shot example in `generate_prompt`, so the model copied it into every prompt and the vision-refine step piled more on top.

Three things keep it out now, and they need to stay in sync:

1. `STYLE_PREFIX` in `imageGenerateUtils.py` fixes the look in code (flat naturalist field-guide plate, matte, muted, even diffuse light) so it cannot drift with the LLM's mood.
2. `NEGATIVE_PROMPT` explicitly blocks the glow/bloom/HDR/cinematic family.
3. `generate_prompt` instructs the model to write *only* creature and habitat descriptors, and names the banned tags. It is now the only call that writes a prompt at all — the review pass returns verdicts and the prompt is edited in code — so there is one place for the tags to creep back in rather than two.

Point 3 is easy to get wrong: an earlier phrasing said the style spec must not be changed ("変更せず"), which the model read as "return the prompt unchanged" and it echoed the input back verbatim. Tell it what to write, not what to leave alone.

`STYLE_PREFIX` stays fixed on purpose — the collection reads as a field guide because every plate is lit and rendered the same way, so variety is bought in the content (body plan, habitat, register, composition) and never in the art direction. The *night observation* composition is the single place anything pulls against it, which is why its directive is written as palette (`cool pale night palette`, `rendered evenly and without glare`) rather than as lighting. If those plates come out muddy, drop the composition rather than loosening the negative.

### Hidden settings

Only the name, the description, and the scientific name reach the finished card. Everything else the pipeline knows is background canon that exists to make the prompt specific, and it is split by who decides it:

- **`pick_traits(species)` rolls dice in code** for danger to humans, population, body plan, composition, size, colour scheme, body surface and register, in that order — each roll looks back at the ones before it, so the plan comes before the composition and both come before the body's size, colour and surface. Asking the LLM to choose any of these gives 25 cards that are all harmless, rare, arthropod and drawn as a centred full-body plate; weighted tables give a spread.

  **Body plan (`BODY_PLANS`) is the one that decides what the creature looks like.** Left alone the model writes a side-on segmented arthropod under *any* species label — `生物`, `鳥` and `草食動物` all came out as bugs — because the only anatomy it was ever shown was `KyomutonProfile`, a six-legged cave insect. Showing an arthropod sheet *is* an instruction to write arthropod anatomy. So the form is rolled in code, like the composition and `STYLE_PREFIX` are, and threaded through **three** calls: description, profile and prompt. Putting it in the profile alone does not work — `generate_description` runs first and the profile is told 「説明文と矛盾しない範囲で」, so once the description has said 硬い外骨格 the plan has already lost. Each row carries a Japanese paraphrase (`ja`) for the two Japanese calls and an English one (`en`) that `_with_directives` prepends to the prompt.

  `SPECIES_KINDS` gates which plans a species may roll, and it only lists species that *name* a form — 鳥 gets 翼, キノコ gets 菌, 甲殻類 gets 節足. Anything not listed (`生物`, `巨大生物`, `分類不明の生物`, and every behaviour-or-standing label like 夜行性生物 or 外来種) draws from the whole table on purpose: those are exactly the species that used to come out as bugs, and they are where the width now comes from. A typo in `SPECIES_KINDS` would degrade silently into "this species gets the whole table", so an assert at import checks every tag against `BODY_PLANS`.

  **`群体型` is a colony, not an animal, and three things have to say so at once.** A creature whose description is 多数の微小な単位が集まる comes back as one large animal built out of those units — a bamboo-textured quadruped with a head and four legs, Swimmy rather than a colony. The plan's `ja` used to end 「ひとつの体をつくっている」 and the description dutifully wrote 融合してより大きな体を構築する, so the prompt asked for one body and got one; it now says the colony has no single outline. The row carries `colonial: True`, and that flag does the rest: `draws_solo()` returns False, because `SOLO_NEGATIVE`'s `multiple creatures, duplicate specimen` is an instruction to collapse a colony into one animal; `draws_foreground_group()` drops `GROUP_DIRECTIVE`, whose 手前の一体 hero specimen is that same instruction in the positive prompt; and the plan's own negative carries the silhouette words (`single large animal`, `head, tail, torso`, `quadruped, four legs`, `mammal, reptile`) on top of `LIMBLESS_NEGATIVE`. The whole-creature plate lost 「head to tail」 from its directive at the same time — `entire body visible end to end` frames a colony, a sac or a disc just as well, and every headless plan was otherwise being told to draw a head. `群生生物` no longer lists 節足 either: a gregarious arthropod writes 多数の個体が絡み合い単一の巨大な塊 into the description and the plate then shows one isopod.

  Composition is one of nine plates, with the trace and body part themselves picked from `TRACES` / `PARTS` — and the part is drawn from what the rolled plan actually has, since each `PARTS` row carries the anatomy it `needs`. A close-up of 「the head」 on a plan whose own negative blocks `head, face, snout` asks the positive and the negative prompt for opposite things, and 「one limb」 on a limbless plan fights `LIMBLESS_NEGATIVE`; both were rollable until the plans grew a `head` flag to be filtered on. The six plans with a front end keep the head and the mouthparts, 放射相称型 keeps 「one limb」 for its arms while losing the head, and everything else is left with the body surface and the sensory organs. Population's `大量発生` entry is the one that reaches the illustration directly: it carries `group=True`, and `draws_group()` turns that into a swarm — but only in the compositions flagged `shows_group`, since nothing can be grouped in a *traces* plate with no animal in it or a close-up of a single body part. The other three population values only colour the profile's behaviour and habitat lines.

  **The spec sheet's first two lines are rolled as well, because they are what the plate is painted from.** 体長 and 体色と質感 were the only lines nobody rolled for, and across the 59 cards then in `src/endemic/` they had collapsed to one look: the colour line said 茶褐 on 23 of them, 白 on 21, 灰 on 16 and 緑 on 16 — everything else together came to fewer than twenty — and 44 of the 59 creatures were a few centimetres long. So `SIZES`, `PALETTES` and `SURFACES` now roll the size, the colour scheme and what the body is covered in, and the three of them multiply out to a look the LLM would not have reached for. Each palette and surface row carries a `kinds` tuple naming the body plans it may be dealt to — 鱗 belongs to a vertebrate and not to a colony, 半透明 to a jellyfish and not to a bird — and an empty tuple means any plan, with an assert at import checking that every plan still has something to draw from. `SPECIES_SIZES` does the same for the four species that name a scale (微生物, 小型生物, 虫, 巨大生物); everything else may be any size, which is where a ten-metre 苔 comes from.

  **The colour is rolled after the composition, because two plates need a particular kind of body.** Camouflage cannot conceal a creature painted to be seen, and the night plate wants the animal to be the lightest shape in the frame, so those two carry `palette: "drab"` / `"light"` and the conspicuous or near-black schemes are filtered out for them. `警告色`'s English had to be written against the diffusion model rather than for it: `drab body with one small patch of vivid warning colour` came back as a shrimp banded head to tail in every colour there is, since `vivid` colours the whole animal whatever the sentence says it applies to. Naming the drab base first and bounding the patch — `drab grey-brown body kept unsaturated except for one small red warning patch` — fixed it. Nothing was loosened in `STYLE_PREFIX`: a muted violet and a near-black are as flat and matte as a muted brown, and the two plates measured came back legible.

  **The roll reaches the plate through the profile, and the card text outranks it.** Handing a fact to `generate_profile` is enough on its own: over those same 59 cards the rolled danger and population reached the sheet on 58 of them, and the prompt call is already told to take its details from the sheet, so 「墨のような黒を基調とし」 comes back as `near-black charcoal and soot palette` without anything being prepended in code. That is also why the description is left out of it — it runs first and mentions colour on only 10 of the 59 cards and size on 13, so there is usually nothing to contradict, and adding a fourth fact to the call that already carries the body plan, the register and the opening rules buys little against the risk of it being copied onto the card verbatim. When the description *does* speak, it wins: the profile is told 「説明文が大きさや色に触れている場合は、そちらに合わせてください」 and the prompt's scale note carries the same clause, so a card that has already said 体長は五ミリ前後 is not illustrated as a three-metre animal because the dice said 数メートル.

  Size is the one of the three that changes the composition rather than the colour, so it is given to `generate_prompt` as well — but only for the plates that show the habitat, since scale can only be read against something else. A plate flagged `magnifies_body` draws the creature against a plain board or fills the frame with it, and there is nothing in it for 「十メートルを超える」 to be ten metres against.

  **Nothing is drawn in cross-section.** A *body cross-section* plate was one of the compositions, and it was wrong for nearly every creature it could be dealt to: a cutaway is a picture of anatomy rather than of an animal, and a body the card never called transparent came back sliced open with its organs laid out. The plate is gone, and `CUTAWAY_NEGATIVE` keeps the diffusion model from reaching for one on its own — its words name the cut itself (`cross-section`, `cutaway view`, `sliced open`, `dissection`, `exposed viscera`), never the internals, so a creature the description *does* call transparent can still show what is inside it. The 「…の体内」 habitats are the exception, and the only place a cut body is right: there the scene is another animal's interior, so `generate_card` matches the field's suffix and passes `get_image(inside_body=True)`, which drops the negative and lets the surrounding body be opened.

  *Distant swarm* is flagged `group_only`, so it is dealt only to a swarming creature and never appears otherwise. Two things follow from it being a landscape: its `limb_mode` is `distant`, because nothing is resolvable at that scale and asking for numerals only makes the model zoom in; and its negative blocks people. Distant views attract human figures on the horizon on their own, and a description that mentions trade or settlement makes it near-certain — `no human presence` in the positive prompt does the opposite of what it says.

  `limb_mode` (`count` / `distant` / `absent`) replaced a pair of booleans that three branches were derived from. The middle branch said 「個体は遠くに小さくしか写りません」, which was written for the swarm plate alone — so any new composition that merely did not want numerals silently inherited "draw it tiny and far away". Set the mode explicitly.

  *Juvenile and adult* is the only plate that sets `solo: False` for a reason other than swarming: `SOLO_NEGATIVE` would delete its second individual. `draws_solo()` is what combines the two, and the colonial plan, which is not one individual to begin with.
- **Every table is a list of weighted rows and `_roll` is the only thing that picks from one.** It takes an optional `fits` predicate for the rows a species or a composition may be dealt — the kinds a body plan allows, the sizes 微生物 may be, the palettes camouflage will accept — and falls back to the whole table when a filter empties it, plus an optional weight function, which is how `LIMB_HEAVY_WEIGHT` bends the composition weights without a second code path. `filled()` is its counterpart on the way out: every entry point calls it once and then reads `traits["composition"]` directly, so a caller that passes no traits at all still gets a complete set rather than each function reaching for its own default.

- **`generate_profile()` fills in the spec sheet** — the ten labelled lines defined by `sampleMonsters.KyomutonProfile` **and** `MizumodokiProfile`, which must stay field-identical; the rolled plan decides which of the two is shown, limbed or limbless. It runs after `generate_description` and is given the description, the plan and the rolled traits, so the sheet agrees with the card text and with the dice. For a limbed plan the limb line is required to carry digits (`脚8本（片側4本）`); for a limbless one the instruction is replaced outright rather than softened, because telling a plant "write the leg count in arabic numerals" grows it legs. The 体長 and 体色と質感 lines are dictated by the rolled size, palette and surface, and the few-shot turn states the ones its own sheet already shows, so the sample demonstrates the answer to the instruction the real turn gives.
- **`generate_description()` picks its voice from `REGISTERS`** — plain field-guide entry, local folklore, research record. The register carries its own few-shot texts and they are swapped wholesale, because an instruction line appended after three samples in one voice loses to the samples every time. The instruction is still there, naming the voice the samples demonstrate, so the two reinforce rather than compete. Register touches this call only: the profile, prompt and scientific-name calls stay pinned to the default-register texts, since what those few-shots teach is the sheet *format*, not the voice. Every register keeps 「3から5文程度」 — that line count lands directly in the caption.

  **The sample turns carry a body plan too, or the model copies the plan straight into the card.** The plan reaches this call as 「この生物の姿は{ja}です。」 appended to the last user turn, and that turn used to be the only one shaped that way: the few-shot showed a request without a plan and an answer, so the model had no example of what to do with the extra clause and lifted it into the prose — 「硬い外骨格と関節のある脚を持ち、体がいくつかの節に分かれている生物。」 as a whole opening sentence. `_SAMPLE_PLANS` now gives each sample creature the plan it actually has (ブリリア 殻を持つ型, ミズモドキ 袋状・球状型, ザトン 節足型) and `_description_request` builds every turn, sample or not, from the same template — so the samples demonstrate the answer to *this* instruction, and each of them describes its own body in its own words rather than restating the phrase. Measured as the longest verbatim run of the `ja` inside the description, over two runs of twelve plans-forced cards each: 4 of 12 cards carried an eight-character run before and 1 of 12 after, the worst case falling from seventeen characters to nine, with the same targets and registers in both arms of the second run. The plan still arrives — 節足型粘菌, 四足歩行の軟体動物, 球状の濾過性生物 — it is paraphrased rather than copied. An assert at import checks every register's samples have a plan, since a new sample would otherwise raise at generation time.

  **The card is a field-guide entry, so every register is third-person and impersonal.** An observation-journal register was tried and dropped: a dated first-person log (「七月十四日、曇。…確認した」) is the one thing a field guide never contains. The research register survives only in the passive — 「採集されている」「報告がある」, never 「採集した」 — because how a specimen came to be collected can be stated as general record but not as the collector's own account. `_OPENING` carries both rules plus the one that matters most: the first sentence names what the creature *is*, as a noun phrase (「水に擬態した原生生物。」). Without it the registers opened on a date, a saying or an anatomical detail and the reader never learned what they were looking at.

  `_OPENING` also keeps the body plan's internal label out of the prose. Passing 「{label}」——{ja}—— put 「植物体型の生物」「節足型の小型生物」 straight onto the card, so the description call gets only the `ja` paraphrase, framed as what the creature *does* with that body rather than a shape to restate — otherwise the model copies the paraphrase back almost verbatim.

  **No `ja` names a taxon, for the same reason.** 植物体型's read 「根と茎と葉に分かれ、地面に根を張る植物のような体」, and a card whose species was 木 opened 「高山帯の岩盤に根を張る植物のような体を持つ生物。」 — the tree had become something merely plant-*like*, and the species word itself was displaced by 生物. The simile is what the row is for when the species names no form (巨大生物 correctly came out 「地面に根を張る植物のような巨大生物。」), but a species that *is* a plant cannot resemble one. Naming the organs instead (「茎と葉を広げ、地面に根を張って立つ体」) leaves the species noun in place: over twelve forced plant cards, 木・草・巨大生物・分類不明の生物 all survived into the opening where the old wording had lost 草 to the exact sentence above. Three of the twelve copied the new phrase into the opening verbatim, which is what the sample turns above are for.

Composition, body plan and the swarm are enforced from code, not by asking the LLM nicely — the same lesson as `STYLE_PREFIX`. `_with_directives` prepends the English directives (`composition['directive']`, then `body_plan['en']`, then `GROUP_DIRECTIVE` for a swarm) to whatever the model returns, skipping any the model already echoed. The body-plan head is skipped entirely when the composition does not draw the creature, or the animal walks back into an empty-habitat plate. That echo check compares comma-separated clauses and counts a head as echoed once two of them appear, with leading `the`/`a`/`an`/`one` stripped: comparing only the first clause missed the model rewriting the subject (`the organism preserved as…` came back as `one specimen preserved as…`) and the same instruction got prepended twice. A `group_only` composition skips `GROUP_DIRECTIVE`, whose foreground specimen would contradict the distant view its own directive already describes, and so does a colonial plan, where that one specimen in full is what turns the colony back into an animal. `_with_directives` is called by `generate_prompt` alone; the review pass reasserts the same heads through `apply_review` when the image contradicts one. Composition and body plan each carry their own extra negative, joined by `extra_negative()` — which also adds `LIMBLESS_NEGATIVE` for any plan whose `limbs` is `none` — and passed through `get_image(extra_negative=...)`. The negative matters most for *traces left behind*: `no creature visible` in the positive prompt is not enough on its own — the model draws the animal anyway — and it takes `live animal, living creature, animal, eyes, face` in the negative to get an empty shed exoskeleton instead of a live one. For that composition the limb-count instructions are dropped as well, since nothing with limbs is in frame.

### Checking the plate against the card

The draft image is not the plate. `generate_card` draws one seed, generates the draft with it, and hands that image to `review_image`, which asks the vision model a single question: does this picture **contradict** the card? The checklist is built in code by `_review_items` from the rolled traits — body plan, the limb numerals `limb_count_phrases` found, the composition, the swarm or the lone specimen, the habitat, and the body's colour and parts against the description and the hidden profile. A *traces* plate is therefore asked only whether the creature stayed out of frame and whether the place matches; a distant swarm is not asked about limb counts at all.

**Not being able to tell is not a mismatch.** The instruction says so outright: an item the image cannot resolve — too small, too far, out of frame — is OK, and only a visible contradiction is NG. A distant swarm can never show the half-millimetre body the description measures, and that is the composition doing its job, not an error. A line that fails to parse or never arrives also defaults to OK, so a confused review costs nothing instead of buying a pointless second generation.

`apply_review` then edits the prompt **in code**, never the model:

- a failed item whose `fix` is a canonical English phrase — the body plan's `en`, the limb numerals, the composition directive, `GROUP_DIRECTIVE` — has that phrase moved to the head of the prompt, deleting the copy already in it rather than stating it twice;
- the short English phrase the model gives for *what the image actually shows* is added to the negative for the retry.

The limbless item is the one that carries no `fix`: `no legs, no arms` cannot be said in a positive prompt at all, so that anatomy is held down by `LIMBLESS_NEGATIVE`, which `extra_negative()` applies to every limbless plan whether the review complained or not.

That note exists to be a negative prompt, so it is sanitised: Japanese is stripped out, phrases over six words or starting with a negation (`no`, `without`, `missing`…) are dropped — `no exoskeleton` in a negative prompt asks for an exoskeleton — at most two survive per item, and a phrase whose every word already appears in the positive prompt is dropped so the two sides cannot fight each other. That last test is word-level rather than substring for a reason: a swarm plate came back `NG single large insect, distant swarm`, and `distant swarm` as a literal string is absent from a prompt that opens `distant wide view of a dense swarm` — negating it would have deleted the composition the card asked for.

**Every plate is reviewed, every retry runs at the same seed, and a plate with nothing NG ends the loop** — an all-clear draft *is* the plate and nothing else is generated. Same seed, same scene, one prompt changed each time: each correction reads as an A/B on one image rather than an unrelated draw.

`REVIEW_RETRIES` (`ENDEMIC_REVIEW_RETRIES`, default 1) caps the corrections, so a card is normally two generations and two reviews, and a clean one is still a single generation. The loop stops early on two conditions besides an all-clear: a round that produces no actionable change — no `fix` phrase moved and no new negative — since the same prompt at the same seed returns the same plate; and a correction that failed to lower the NG count, because a correction that did not help is poor evidence that the next one will.

The default is 1 on measurement, not principle. Three cards run at 2 retries took 171–193s each against 63–66s for the single-retry pass, and the third plate was **never** the one kept: one card improved on its first correction (2 NG → 1) and two were worse or level, so the extra generation bought nothing but time. Raise it when a run matters more than the clock.

**The card keeps the plate with the fewest NG items, not the last one**, resolving ties in favour of the earlier round. A correction can trade one mismatch for another: the 袋状・球状型 card below lost its fish fins and grew legs instead. Scoring every round and keeping the best means a round that makes things worse is simply discarded, and it is why the last plate is reviewed too even though nothing can act on the verdict.

This replaced a pass that handed the draft to the model and asked it to rewrite the prompt freely. Measured over the 28 cards then in `src/endemic/`, that pass returned the prompt **byte-identical on 11 of them** and mostly reordered clauses on the rest: "rewrite this prompt" plus "keep these numerals exactly" reads as "return the input", the same echo failure as the style spec above. A verdict cannot be echoed.

What the loop cannot do is out-argue the diffusion model. The judge is a sampled LLM call, so its verdicts carry noise — the same plate reviewed twice may not score identically, and a tie between rounds is decided by the tie-break rather than by quality. Anatomy the model simply will not draw, such as a body with no head and no limbs, stays wrong however many rounds it gets; that is what the plan-level negatives are for, and past three generations a card costs more than it is worth. Raise `ENDEMIC_REVIEW_RETRIES` for a careful run, set it to `0` to review once and keep whatever the draft was. The judge's own false positives are part of the bill: a *close-up of the mouthparts* plate was marked NG on composition with the note `mouthparts, teeth` — the very thing its directive asked for — in all three rounds, which is two wasted generations that the stop rule now cuts to one.

### Correcting the card against the plate

The plate is settled by the time the review loop ends, so the last pass corrects the other side. `review_description` shows the chosen plate and the description numbered one sentence per line and asks which sentences the picture contradicts; `apply_proof` splices the answer **in code**, copying an OK sentence byte for byte and replacing only one the judge returned as 「番号: NG 書き直した文」. The register, the sentence count and the caption's height therefore survive a correction, and a line that fails to parse leaves its sentence alone, as in the image review.

**What the plate may not correct is what the dice already decided.** Over the first eight cards the pass ran on, every card was edited and six of the edits were wrong, all in the same way: 二翼二脚 became 四翼 because a distant swarm looked four-winged, 環形動物 became the invented 環状動物, a *traces* plate turned 「…する巨大生物。」 into 「…する巨大生物の足跡。」, a coral-reef creature was moved out to open water, and one answer rewrote three sentences by shifting each one's text into the next. So the call is told that the habitat, the species, the body plan and the names are right and that a plate which disagrees with them is the plate's problem — the same division as the image review, which is where a wrong plate is supposed to be fixed. The rest is enforced in code, not asked for:

- **The opening sentence is never rewritten.** It is the one that says what the creature is, and it is where every one of those edits but the shift landed; a verdict on sentence 1 is ignored.
- **At most one sentence is corrected per card.** Two or more NG verdicts describe a plate that disagrees with the whole card rather than a sentence that needs a word changed, and every multi-sentence answer measured was a mangling; more than one surviving correction drops them all.
- **An answer that repeats another sentence of the description verbatim voids the whole round**, because that is the shift above and the numbering can no longer be trusted.
- A replacement longer than 1.5× the original is dropped — 「…ではなく、…」 rewrites arrive that way and they are not field-guide prose — and so is one that loses the species or habitat word the original carried, or that contains a hidden trait label. The pass is not given the hidden profile at all: when it was, 「人間には全く無害」 and 「限られた場所にのみ局所的に生息する」 went onto the card verbatim, which is exactly what *Hidden settings* exists to prevent.
- A composition that does not draw the creature skips the pass outright. The animal is deliberately out of frame, so there is nothing in the plate to read the description against.

Measured after those rules: eight cards, four corrected sentences, none in an opening, none leaking, and the one card whose plate was plainly wrong — a 植物体型 drawn as a four-legged animal — was left alone, which is the intended answer. The pass costs one vision call, 1.4–2.2s. Both texts ride in the PNG as `draft_description` and `proofed_description`, so what it changed stays measurable.

### Fixing the Japanese itself

The two passes above judge the card against the plate. Neither of them reads the Japanese, and the model writes a broken sentence often enough to matter: 「入洞が避けるのが慣わしとなっている」, 「体表は粘液を分泌し」, 「根は深く張り巡らし、土壌の安定化に寄与している」. `polish_description` is one text-only call, ~2s, that runs **after** the plate proofread — that pass edits the card as well, so anything it introduces has to be readable too — and it uses the same numbered protocol: one sentence per line, 「番号: OK」 or 「番号: NG 直した文」, spliced back by the same `apply_proof`.

What it is allowed to change is decided in code, because the model asked to "make this natural" restyles the whole card. Measured over the 92 cards in `src/endemic/`, the first version rewrote **34 of their 353 sentences**, and only about a third of those were fixes: it hedged 「利点がある」 into 「利点があると考えられる」, turned 「捕らえて生きている」 into 「捕らえて食べている」, dropped a clause of anatomy, and rewrote an opening 「…する生物。」 into 「…する生物である。」. Four guards cut that to **14 sentences on 13 cards**, nearly all of them real:

- **The opening sentence is never rewritten**, the same rule as the plate proofread and for the same reason — the noun-stop is the house style, so 「生物である。」 is a restyle wearing a correction's clothes.
- **No kanji may appear that is not already somewhere in the description.** A grammar fix is almost entirely kana work — 張り付き→張り付いて, 報告され→報告されており, 体表は→体表から — while new content arrives as new kanji, which is how 食べている and 考えられる were caught. It costs the occasional real fix: 色素班→色素斑 is a genuine typo the rule throws away.
- **An edit that only reaches the last six characters is dropped.** Nearly all the noise was sentence-final aspect (摂取する→摂取している, 暗褐色をしている→暗褐色である) — not errors, just the model's preference, and rejecting the tail removed twelve of them at the cost of the rare 主述 fix that lives there.
- **The sentence may not lose more than six characters**, which is what stopped a clause of body plan being deleted, and the numerals in it have to survive character for character so 五ミリ cannot become 五センチ.

At most two sentences are corrected per card (`POLISH_MAX_EDITS`); more than that is a rewrite, and the round is voided whole, as in the other two passes. A replacement identical to the original is dropped, which is also what catches the pass echoing back the plate proofread's own correction.

**Turning the model's reasoning up does not do this job.** `--reasoning off` is set on `llama-server` for the reason under *LLM* below, but it can be lifted per call — `chat_template_kwargs: {"enable_thinking": true}` re-enables it for one request even with the flag set, and the thinking comes back in `reasoning_content`, so `call_llm`, which reads `delta.content`, would never see it. Measured on six descriptions generated both ways: thinking cost **21–52s against 3–5s**, and the Japanese did not get better. It got looser — one answer came back 「腐朽した組織を分解していることが報告がある」, two abandoned the sentence-per-line shape of the few-shot for a single paragraph, and one wrote 「四足歩行の脊椎動物」, copying the body plan into the prose that *Hidden settings* spends three paragraphs keeping out. Thinking is deliberation about the task, and writing a grammatical sentence is not a task the model is failing to think about.


### Keeping the limb count stable

The diffusion model decides limb counts on its own unless the prompt names a number, and it will happily draw a six-legged crab. Nothing in the prompt used to give it one — the few-shot example in `generate_prompt` said `thin twitching limbs`, so the model copied that vagueness into every prompt. Three pieces now pin the number down:

1. The count comes from the hidden profile's limb line, the few-shot example states one (`six thin twitching legs, three legs on each side, two short antennae, no other limbs`), and `generate_prompt` instructs the model to carry that count over as an English numeral, add the left/right split, follow the description when it states a number, and avoid `many legs` / `numerous limbs` style vagueness. `no other limbs` and a single specimen keep unrequested appendages and extra creatures out of the frame.
2. The vision pass would otherwise "correct" the prompt towards whatever the draft image happens to show, which is exactly the wrong direction. `limb_count_phrases` pulls the numeral phrases out of the prompt (regex over number + appendage noun) and they become one checklist item, so the vision model is only ever asked *whether the image contradicts them* — it never writes the prompt, and `apply_review` puts the same numerals back at the head when the item fails. Asking it to rewrite while keeping the numerals is what produced the verbatim echo described under *Checking the plate against the card*.
3. `NEGATIVE_PROMPT` carries the anatomy block — `extra limbs` / `missing limbs` / `fused limbs` / `duplicated limbs` and friends. `multiple creatures, duplicate specimen` sits apart in `SOLO_NEGATIVE`, added by `get_image(solo=True)`, since a second specimen in frame otherwise makes the count unreadable regardless of what the prompt asked for. Swarming creatures and colonies are the exception and pass `solo=False`; there the count is kept readable by composition instead — `GROUP_DIRECTIVE` puts one specimen in the foreground in full and the rest smaller and further back, and both prompt calls are told only that foreground individual has to be countable.

Those three carry a number through the pipeline faithfully, which is not the same as the number being drawable. Two more bound it:

- `generate_profile` caps any one kind of appendage at `MAX_LIMBS` (8), and each body plan carries its own `limb_cap` which is combined with `min()` — so a plan can only ever make the ceiling stricter, never looser. A spec sheet that says 脚14本 breaks the plate whatever the species is.
- A plan whose `limbs` is `none` takes a different branch in all three of profile, prompt and the review checklist, rather than a softened version of the same one. It is also why `_NUMBER` matches `no` and `zero`: the model writes `zero legs, no other limbs`, `limb_count_phrases` returned nothing for it, and the pass then fell through to "write the numerals" — on a plant. Such a plan also gets `LIMBLESS_NEGATIVE` (`legs, arms, paws, claws, hooves, standing on legs, walking`) from `extra_negative()`, because `no legs, no arms` in the *positive* prompt does nothing at all: the text encoder has no negation, the same reason `no human presence` fails on the distant-swarm plate. Measured on one 袋状・球状型 card: the draft came back a fish, the corrected prompt alone turned it into a four-legged turtle, and only with the limb words in the negative did it come back a limbless sac.
- `pick_traits` withholds the compositions flagged `magnifies_body` from limb-heavy creatures. Ten walking legs plus chelipeds plus antennae is past what the model keeps straight however the prompt is worded, and the larger the body is drawn the more obvious the mess. The test is now the body plan's `limb_heavy` flag rather than the species, since the problem follows the anatomy, not the label — `LIMB_HEAVY_SPECIES` (甲殻類) survives only as a backstop for a species pinned by hand. Such a creature is dealt a habitat scene, a trace, camouflage, a night plate or a distant swarm instead. `LIMB_HEAVY_WEIGHT` is the multiplier applied to those compositions' weights: 0 keeps them out entirely, 0.2 lets them through occasionally. Whatever it is set to, at least one composition has to keep a non-zero weight — `_roll` falls back to an unweighted choice rather than letting `random.choices` raise, but a table that needs the fallback is a table that is mis-weighted.

### Web UI (`web/`)

`webui` is one button. Pressing it runs `pipeline.generate_card()` and shows the card that comes
out; there is nothing else on the page. Like `app` it holds no models of its own and only talks to
`llama-server` and `comfyui` over HTTP.

`web/server.py` is four routes and a dict:

- **`POST /api/generate`** starts one card on a worker thread (`asyncio.to_thread`, since every
  call inside it blocks) and returns at once. Pressing again while one is running gets a 409:
  `llama-server` and `comfyui` together already fill the card (22.2GB of 24), so a second
  concurrent card would not fit. That single flag is the whole of the scheduling.
- **`GET /api/status`** is `{running, image, error}`, which the page polls every two seconds.
  Reloading part way through a three-minute generation picks the run back up, and a failure leaves
  its reason on screen with the button pressable again — one bad card costs nothing but the press.
- **`GET /api/image/<name>`** serves the finished PNG out of `src/endemic/`. The name is matched
  against a no-separator pattern and the resolved path checked to be inside that directory.
- **`/`** and **`/static/`** are the page.

No `emit` is passed, so `call_llm` prints the streamed tokens to stdout exactly as it always has.
Follow a generation with `docker compose logs -f webui`.

Everything about a card is in the PNG itself (see *Generation pipeline*), so there is nothing for
this side to store: no database, no sidecar files, and no state that outlives the process beyond
`src/endemic/`.

The page is `web/static/` — plain HTML/CSS/JS, no build step, mounted rather than baked into the
image so an edit needs only `docker compose restart webui`.

### Breaking the caption into lines

`getLineBreak` asks `janome` where the words are and fills each line greedily, and what it is really deciding is where a word *starts*. The first version started one at every 名詞, which is not where Japanese words begin: janome hands back a compound as several nouns in a row, so over the 92 cards in `src/endemic/` **69 of 457 line breaks fell inside a word** — 四/本の脚, 約十五/センチメートル, 登山/者, 黄/褐色, 半/透明. `_starts_word` now refuses a break between two nouns, between a noun and its 接尾, after a 接頭詞, between a 動詞 and the 動詞 that continues it (這い/回る), and between a サ変接続 noun and the する that follows it (固定/し) — that last one was introduced by this very rewrite, since 動詞 became a place a line may begin.

Giving verbs, adverbs and adjectives their own word start is what pays for the compounds: there are fewer places to break inside a noun phrase and more everywhere else, and the result is **448 lines instead of 457 at 84.4% average fill instead of 82.8%**, with no word split anywhere. A caption that is both shorter and more even is the whole of the improvement; nothing else in `add_caption` changed.

`HEAD_FORBIDDEN` / `TAIL_FORBIDDEN` carry 禁則: no line may open on 、。）」 or a small kana, and none may end on an opening bracket. Neither the old wrapper nor the new one violated either over those 92 cards, because punctuation attaches to the word before it, but the rules are enforced where a word is too long for a line of its own and has to be cut mid-word — the only path that can land on such a character. The `Tokenizer` is built once per process rather than once per call; it is the expensive part of janome and a card only wraps one description.

### LLM (`llama-server`)

Qwen3.8-27B is a dense multimodal model, so it handles both the text calls and the vision call — no separate VL model. Three settings are load-bearing:

- **`--reasoning off`**. Qwen3.8 defaults to thinking mode at `reasoning_effort=xhigh` and will burn the entire token budget reasoning about a three-sentence creature description, returning empty `content`. Our calls are all short generations, so thinking is turned off and the sampling params follow Qwen's published *non-thinking* recommendation (temp 0.7, top-p 0.8, top-k 20, presence-penalty 1.5).
- **`--presence-penalty 1.5`**, from that same recommendation, is what stops repetition loops. Under the previous Q2_K_XL model a loop once ran to the full 32k context and got llama-server OOM-killed.
- **`--cache-ram 0`**. llama-server's prompt cache lives in **host RAM**, and its default cap is `8192` MiB — more than this host's entire 3.8GiB of RAM. `--cache-idle-slots` is also on by default, so every incoming task evicts the idle slots' KV from VRAM into that cache. Measured at **457MiB retained per request**, growing linearly and never released: RSS pinned at the ~2.4GiB RAM ceiling, the rest spilled to swap, and around request 17 the kernel's OOM killer took llama-server out (`exit 137`, `constraint=CONSTRAINT_NONE ... global_oom`). One creature card is five LLM calls (it was four before the hidden profile was added), so this OOMed after three or four cards. That is what `restart: unless-stopped` on the service is for — before it was added, llama-server stayed dead afterwards and every later notebook cell failed with a connection error until someone ran `docker compose up` by hand. Note the healthcheck returned `{"status":"ok"}` until four seconds before the kill — the `depends_on: service_healthy` gate cannot catch this, since it is a failure under load rather than at startup. The cache is worth little here (each card's prompts are near-unique), so it is disabled outright; with more host RAM, 512–1024 would be reasonable.

**The projector comes from `ggml-org`, not `unsloth`.** The file at `unsloth/Qwen3.8-27B-GGUF/mmproj-F16.gguf` is byte-identical to the Qwen3.5 projector (`projection_dim` 2048) and llama-server refuses to start with it, since Qwen3.8-27B has `n_embd` 5120. `ggml-org/Qwen3.8-27B-GGUF/mmproj-Qwen3.8-27B-Q8_0.gguf` is the correct one.

llama-server also warns that Qwen-VL wants `--image-min-tokens 1024` for grounding tasks. Our vision call only describes an image rather than locating things in it and works without the flag; raising it would cost VRAM we do not have.

### LLM client (`textGenerateUtils.py`)

Uses the `openai` Python client pointed at the local llama-server (`LLAMA_SERVER_URL` env var, default `http://llama-server:8080/v1`). Responses are streamed and echoed token-by-token as they arrive — to stdout by default, or to whatever `token_sink` is set to (see *Web UI*). `call_llm` sets `max_tokens` (default 2048) and warns when a generation is truncated — without a cap a repetition loop runs until it exhausts the context and takes llama-server down with it.

### Tests

`src/tests/` is 93 pytest tests over the pure functions, and it runs in about four seconds without
the GPU, the LLM or ComfyUI:

```bash
docker compose exec app python -m pytest /mnt/tests -q
```

They cover the four places where behaviour is decided in code rather than by a model, which is
exactly where a regression is invisible: where a line may break (`test_linebreak.py`), what a
correction may change to a sentence (`test_sentences.py`), how a verdict becomes a prompt
(`test_review.py`), what the dice may deal (`test_traits.py`) and what each call is told
(`test_prompt.py`). Every rule that *Hidden settings*, *Correcting the card against the plate* and
*Breaking the caption into lines* describe has a test named after it, and the table schemas are
asserted key by key, so adding a row to `COMPOSITIONS` and forgetting `palette` fails a test
rather than a generation.

**They were written against mutations, not against the code.** A test that cannot fail is worse
than no test, and three of the first batch could not: the suffix test passed because the
noun-after-noun rule already covered 登山/者; `_parts` was only asserted to be non-empty, so
deleting its head filter changed nothing; and the apply_review test used a fix phrase that was
already at the head of the prompt, so promoting it again was a no-op. The polish guards were worse
— removing the new-kanji rule broke nothing, because 生きている→食べている is also a tail-only edit
and the tail rule caught it. Each guard now has a case that trips **it and nothing else**, checked
by measuring the distance, the shortening, the tail and the kanji of every case. Twenty-four
mutations — one per rule, each deleting or loosening it in the source — are all caught.
