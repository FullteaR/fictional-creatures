# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project does

Generates fictional creature ("endemic life") cards in the style of a field guide. Each card combines:
1. A Japanese monster name generated by a Markov chain trained on `src/monsterNames.txt`
2. A description and scientific name generated via LLM (Qwen3.5 running locally via llama.cpp)
3. An image generated by the Anima model (`novaAnimeAM_v40.safetensors`), served by a ComfyUI container over HTTP
4. A composite image with styled caption overlay rendered using `ipagp.ttf`

Output images are saved to `src/endemic/`.

## Running the project

All services run via Docker Compose. GPU is required.

```bash
# Start everything (downloads LLM, starts llama-server + ComfyUI, starts Jupyter)
docker compose up

# Access Jupyter notebook
# http://localhost:28080
# Open src/monster-generator.ipynb and run cells

# ComfyUI web UI (useful for debugging workflows by hand)
# http://localhost:8188
```

The `model-downloader` service runs first, downloading `unsloth/Qwen3.5-35B-A3B-GGUF` (Q2_K_XL quant) into `./models/`. The `llama-server` service then serves it via llama.cpp at `http://llama-server:8080/v1`. The `comfyui` service serves image generation at `http://comfyui:8188`, with `./models/comfyui` mounted as its model root. The `app` service runs JupyterLab at port 28080, with `./src` mounted at `/mnt`.

Image model weights are **not** downloaded automatically — see *Image models* below.

## Architecture

### Generation pipeline (`src/monster-generator.ipynb`)

1. **Name**: `MarkovMonsterNameGenerator` (bigram Markov chain) generates a Japanese katakana name, rejecting names too similar (Levenshtein distance ≤ 1-2) to training names.
2. **Target string**: Combines random habitat (`fields`) + random species type (`spicies`) + name into a description target like `「深海にて観測される架空の魚「ミロカルガン」」`.
3. **Text generation** (`textGenerateUtils.py`): one LLM call each, few-shot prompted with `sampleMonsters.py` examples:
   - `generate_description`: 3-5 sentence Japanese description
   - `generate_prompt`: English image prompt (comma-separated descriptors; Anima's Qwen text encoder has no 77-token limit, so long prompts pass through intact)
   - `generate_scientific_name`: two-word Latin scientific name, reduced to its first line
4. **Image generation** (`imageGenerateUtils.py`): POSTs a ComfyUI API-format workflow to `comfyui:8188`, polls `/history/{prompt_id}`, fetches the PNG via `/view`. Generates at 1280×768 and downscales to 800×480. A draft image is generated first, fed back to the model by `refine_prompt_with_image` (the LLM sees its own output and rewrites the prompt), and the refined prompt produces the final image. **This is the only refinement pass in the pipeline** — an earlier blanket self-refinement loop over every text call was removed; it doubled the LLM calls and, on the scientific name, "improved" a two-word binomial into a paragraph of Japanese, whose width then pushed the whole caption off the canvas.
5. **Captioning** (`imageGenerateUtils.py:add_caption`): Uses `janome` for Japanese word-boundary tokenization to wrap description text, overlays semi-transparent rounded rectangle at a random corner of the image. The corner offsets are clamped to the canvas, so unexpectedly long text degrades to a top-left caption rather than being drawn off-screen.

### Image client (`imageGenerateUtils.py`)

`get_image()` builds the ComfyUI workflow graph in code (`_build_workflow`) rather than loading a saved JSON, mirroring the official *Text to Image (Anima Base v1.0)* template: `UNETLoader` → `CLIPLoader`(type `stable_diffusion`) → `CLIPTextEncode` ×2 → `EmptyLatentImage` → `KSampler`(euler/simple, 30 steps, cfg 4) → `VAEDecode` → `SaveImage`.

Anima ships as three separate files, so all three loaders are needed — a single-file SDXL checkpoint would use `CheckpointLoaderSimple` instead. Override any of them via `COMFYUI_DIFFUSION_MODEL` / `COMFYUI_TEXT_ENCODER` / `COMFYUI_VAE`, and the server via `COMFYUI_URL`.

### Image models

Weights live under `./models/comfyui/` (gitignored) in ComfyUI's standard layout. Anima is the only image model kept locally — an SDXL-family checkpoint would go in `checkpoints/` and need a `CheckpointLoaderSimple` workflow instead of the three loaders below:

| Path | File | Source |
|------|------|--------|
| `diffusion_models/` | `novaAnimeAM_v40.safetensors` (3.9GB, Anima arch, 2.09B params) | [Civitai: Nova Anime AM](https://civitai.com/models/2604424) |
| `text_encoders/` | `qwen_3_06b_base.safetensors` (1.2GB) | [HF: circlestone-labs/Anima](https://huggingface.co/circlestone-labs/Anima) |
| `vae/` | `qwen_image_vae.safetensors` (243MB) | same HF repo |

### LLM client (`textGenerateUtils.py`)

Uses the `openai` Python client pointed at the local llama-server (`LLAMA_SERVER_URL` env var, default `http://llama-server:8080/v1`). Responses are streamed, echoed to stdout token-by-token as they arrive, and returned as a joined string (thinking blocks included).

### Key files

| File | Purpose |
|------|---------|
| `src/monster-generator.ipynb` | Main orchestration notebook |
| `src/textGenerateUtils.py` | LLM calls: description, SD prompt, scientific name |
| `src/imageGenerateUtils.py` | ComfyUI HTTP client + caption rendering |
| `src/MonsterNameGenerator.py` | Markov chain name generator |
| `src/sampleMonsters.py` | Few-shot example texts used in LLM prompts |
| `src/monsterNames.txt` | Training data for name generator |
| `models/comfyui/` | Image model weights, ComfyUI layout (not in git) |

### Docker services

| Service | Dockerfile | Role |
|---------|-----------|------|
| `model-downloader` | `Dockerfile.model-downloader` | One-shot: downloads GGUF from HuggingFace |
| `llama-server` | `Dockerfile.llama-server` | Builds llama.cpp from source, serves Qwen3.5 |
| `comfyui` | `Dockerfile.comfyui` | ComfyUI from git master, serves image generation on 8188 |
| `app` | `Dockerfile` | JupyterLab only — orchestrates the other two over HTTP |

`comfyui` uses `pytorch/pytorch:2.10.0-cuda13.0-cudnn9-devel`. `app` is plain `python:3.12-slim` and needs **no GPU and no PyTorch** — since both models moved behind HTTP, its only dependencies are jupyter, matplotlib, tqdm, Pillow, janome, python-Levenshtein and openai. Anything reintroducing in-process inference there would need the GPU reservation and CUDA base image back.

Only `llama-server` and `comfyui` touch the GPU. On a 24GB card the Q2_K_XL LLM plus Anima (~5.7GB measured) fits; Q4_K_XL (21GB) does not fit alongside ComfyUI.
